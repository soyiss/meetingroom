# 🏢 회의실 예약 시스템

> Spring Boot와 PostgreSQL을 활용한 웹 기반 회의실 예약 시스템

사용자가 회의실을 조회하고 원하는 날짜와 시간에 예약할 수 있으며,  
예약 현황 조회, 예약 수정 및 취소, 전체 예약 캘린더, 관리자 예약 관리 기능을 제공하는 웹 서비스입니다.

Spring Boot, MyBatis, PostgreSQL을 기반으로 직접 설계하고 구현했으며,  
예약 중복 검사, 사용자 권한 검증, 비밀번호 암호화, 세션 정보 보호,  
단위 테스트 및 Cloudflare Tunnel을 이용한 외부 접속 환경까지 구현했습니다.

---

## 📌 프로젝트 소개

### 개발 목적

회의실을 예약할 때 발생할 수 있는 **예약 시간 중복 문제**와  
전체 예약 현황을 확인하기 어려운 문제를 해결하는 것을 목표로 개발했습니다.

사용자는 로그인 후 회의실별 수용 인원과 예약 현황을 확인하고 원하는 날짜와 시간에 회의실을 예약할 수 있습니다.

예약 이후에도 자신의 예약을 조회하고 수정하거나 취소할 수 있으며,  
전체 예약 현황은 캘린더 형태로 제공하여 날짜별 예약 상태를 한눈에 확인할 수 있도록 구현했습니다.

또한 `admin` 관리자 계정을 통해 전체 예약을 조회하고 예약을 취소할 수 있도록 관리자 기능을 추가했습니다.

프로젝트 구현 이후 코드 리뷰를 통해 발견된 권한 검증, 비밀번호 보안, 입력값 검증 등의 문제를 개선하고  
JUnit과 Mockito를 이용한 단위 테스트를 추가했습니다.

## 🏗 프로젝트 구조

```text
Browser
   │
   ▼
Controller
   │
   ▼
Service
   │
   ▼
Mapper
   │
   ▼
PostgreSQL
```

각 계층의 역할을 분리하여 유지보수하기 쉽도록 구성했습니다.

- **Controller** : HTTP 요청 및 응답 처리
- **Service** : 예약 중복 검사 등 비즈니스 로직 처리
- **Mapper** : MyBatis를 이용한 SQL 처리
- **Domain** : 데이터 객체 관리
- **DTO** : 필요한 데이터만 전달하기 위한 객체 관리
- **Config** : BCrypt 등 프로젝트 전역 설정 관리

### 📅 회의실 예약

사용자가 원하는 회의실과 날짜, 시간을 선택하여 예약할 수 있습니다.

예약 과정에서 다음과 같은 유효성 검사를 수행합니다.

- 오늘 이전 날짜 예약 방지
- 현재 시간 이전 예약 방지
- 시작시간 / 종료시간 유효성 검사
- 시작시간보다 종료시간이 빠른 경우 예약 방지
- 시작시간과 종료시간이 같은 경우 예약 방지
- 기존 예약과 시간 중복 여부 검사

---

### ⏰ 예약 시간 중복 검사

동일한 회의실에 이미 예약된 시간과 새로운 예약 시간이 겹치는 경우 예약을 차단합니다.

다음 조건을 이용하여 예약 시간의 겹침 여부를 검사합니다.

```text
기존 예약 시작시간 < 새로운 예약 종료시간
AND
기존 예약 종료시간 > 새로운 예약 시작시간
```

예를 들어 다음과 같은 경우 예약이 불가능합니다.

```text
기존 예약
10:00 ───────── 12:00

새로운 예약
       11:00 ───────── 13:00
```

반면 기존 예약이 끝나는 시간부터 새로운 예약을 시작하는 경우에는 예약할 수 있습니다.

```text
기존 예약
10:00 ───────── 12:00

새로운 예약
                  12:00 ───────── 13:00
```

로그인한 사용자는 자신의 예약 내역을 확인할 수 있습니다.

- 내 예약 목록 조회
- 예약 날짜 및 시간 확인

예약 취소 시 데이터를 실제로 삭제하지 않고 예약 상태를 변경하도록 구현했습니다.

```text
예약완료
   ↓
예약취소
```

이를 통해 취소된 예약의 상태를 데이터에서 확인할 수 있도록 구성했습니다.

## 💡 주요 구현 포인트

### 1. 예약 중복 검사

단순히 시작시간이 같은지 확인하는 것이 아니라 예약 시간 구간 자체가 겹치는지 검사했습니다.

```text
기존 시작시간 < 새로운 종료시간
AND
기존 종료시간 > 새로운 시작시간
```

이를 통해 동일한 회의실에서 시간대가 겹치는 예약을 방지했습니다.

---

### 2. 예약 수정 시 중복 검사

예약 수정 시 현재 수정 중인 예약까지 중복으로 판단하지 않도록 현재 예약 ID를 제외하고 중복 검사를 수행했습니다.

```sql
AND id != #{id}
```

이를 통해 기존 예약을 자기 자신과 중복되는 것으로 판단하는 문제를 방지했습니다.

---

### 3. 예약 시간 유효성 검증

예약 등록 및 수정 과정에서 시작시간과 종료시간을 비교하여 잘못된 시간 입력을 방지했습니다.

```text
시작시간 < 종료시간
```

조건을 만족하지 않는 경우 예약을 진행하지 않고 사용자에게 오류 메시지를 전달하도록 구현했습니다.

---

### 4. 예약 취소 상태 관리

예약 취소 시 데이터를 실제로 삭제하는 대신 예약 상태를 변경하도록 구현했습니다.

```text
예약완료
   ↓
예약취소
```

이를 통해 취소된 예약도 데이터에서 확인할 수 있도록 구성했습니다.

---

### 5. 예외 발생 시 예약 화면 유지

예약 중복 등의 오류가 발생했을 때 단순히 오류 페이지만 표시하지 않고 사용자가 예약 화면에서 계속 작업할 수 있도록 처리했습니다.

오류 발생 시 다음 데이터를 다시 전달합니다.

- 회의실 정보
- 기존 예약 현황
- 오류 메시지

이를 통해 예약 실패 후에도 현재 회의실의 예약 상황을 바로 확인할 수 있도록 구현했습니다.

---

### 6. 세션 기반 로그인

`HttpSession`을 이용하여 로그인한 사용자의 정보를 저장했습니다.

```text
로그인
  ↓
LoginUser DTO 생성
  ↓
loginMember 세션 저장
  ↓
예약 기능 접근
  ↓
내 예약 조회
```

로그인하지 않은 사용자가 예약이나 내 예약 현황에 접근하는 경우 로그인 페이지로 이동하도록 처리했습니다.

---

### 7. 세션 내 민감정보 보호

로그인 성공 시 `Users` 객체 전체를 세션에 저장하지 않고 비밀번호를 제외한 사용자 정보만 `LoginUser` DTO에 담아 세션에 저장하도록 변경했습니다.

이를 통해 세션에 불필요한 비밀번호 정보가 포함되지 않도록 구성했습니다.

---

### 8. 관리자 접근 제한

관리자 페이지 링크를 화면에서 숨기는 것뿐만 아니라 Controller에서도 관리자 여부를 확인하도록 구현했습니다.

```text
/admin 요청
    ↓
로그인 여부 확인
    ↓
username == admin 확인
    ↓
관리자 페이지 접근
```

일반 사용자가 `/admin` URL을 직접 입력하는 경우에도 관리자 페이지에 접근할 수 없도록 처리했습니다.

---

### 9. 예약 수정 및 취소 권한 검증

예약 ID만 알고 있다고 해서 다른 사용자의 예약을 수정하거나 취소할 수 없도록 권한 검증을 추가했습니다.

```text
예약 수정 / 취소 요청
        ↓
로그인 여부 확인
        ↓
예약 존재 여부 확인
        ↓
관리자 또는 예약자 본인인지 확인
        ↓
예약 수정 / 취소
```

이를 통해 다른 사용자의 예약을 임의로 수정하거나 취소할 수 있는 문제를 방지했습니다.

---

### 10. 비밀번호 암호화

사용자의 비밀번호를 평문으로 저장하거나 비교하지 않고 BCrypt를 이용하여 암호화된 비밀번호를 저장합니다.

로그인 시 사용자가 입력한 비밀번호와 DB에 저장된 BCrypt 암호화 비밀번호를 비교하여 인증합니다.

```text
사용자 입력 비밀번호
        ↓
PasswordEncoder
        ↓
BCrypt 비밀번호 비교
        ↓
로그인 성공 / 실패
```

---

### 11. DB 접속정보 환경변수 분리

DB 접속정보를 `application.yaml`에 직접 하드코딩하지 않고 환경변수를 통해 관리하도록 구성했습니다.

```text
DB_URL
DB_USERNAME
DB_PASSWORD
```

`application.yaml`에서는 환경변수를 참조하도록 구성하여 GitHub에 실제 DB 비밀번호가 노출되지 않도록 했습니다.

---

### 12. FullCalendar를 이용한 예약 시각화

DB에서 조회한 예약 정보를 FullCalendar 이벤트로 변환하여 캘린더에 표시했습니다.

예약자별로 서로 다른 색상을 적용하여 여러 사용자의 예약을 쉽게 구분할 수 있도록 구현했습니다.

또한 캘린더 하단에 예약자별 색상 범례를 제공하여 색상의 의미를 쉽게 확인할 수 있도록 구성했습니다.

---

### 13. 예약 서비스 단위 테스트

예약 기능의 주요 비즈니스 로직이 정상적으로 동작하는지 검증하기 위해 JUnit과 Mockito를 활용한 단위 테스트를 작성했습니다.

다음과 같은 예약 상황을 테스트했습니다.

- 정상적인 예약 성공
- 종료시간이 시작시간보다 빠른 경우 예약 실패
- 시작시간과 종료시간이 같은 경우 예약 실패
- 기존 예약과 시간이 중복되는 경우 예약 실패

`ReservationMapper`는 Mockito의 Mock 객체로 대체하여 실제 데이터베이스에 접근하지 않고 `ReservationService`의 비즈니스 로직만 독립적으로 테스트했습니다.

총 4개의 예약 관련 테스트를 작성했으며 모두 정상적으로 통과했습니다.

## 🔒 보안 및 예외 처리

프로젝트 구현 과정에서 코드 리뷰를 통해 발견된 문제를 개선하고 사용자 권한과 민감한 정보를 보호하기 위한 보안 처리를 적용했습니다.

### 권한 검증

예약 수정 및 취소 요청 시 예약 ID만으로 접근할 수 없도록 로그인한 사용자의 정보와 예약 소유자를 비교하여 권한을 확인합니다.

- 로그인 여부 확인
- 예약 존재 여부 확인
- 예약자 본인 여부 확인
- 관리자 계정의 예약 관리 권한 확인

이를 통해 다른 사용자의 예약을 임의로 수정하거나 취소할 수 있는 문제를 방지했습니다.

### 비밀번호 보안

기존 평문 비밀번호 비교 방식에서 BCrypt 기반 비밀번호 검증 방식으로 개선했습니다.

비밀번호는 DB에 암호화된 형태로 저장하며, 로그인 시 `PasswordEncoder.matches()`를 이용하여 사용자가 입력한 비밀번호와 비교합니다.

### 세션 정보 보호

로그인 성공 시 `Users` 객체 전체를 세션에 저장하지 않고 비밀번호를 제외한 사용자 정보만 `LoginUser` DTO에 담아 세션에 저장하도록 변경했습니다.

### DB 접속정보 보호

DB URL, 사용자명, 비밀번호 등의 접속정보를 소스코드에 직접 작성하지 않고 환경변수로 분리했습니다.

이를 통해 GitHub와 같은 원격 저장소에 실제 DB 비밀번호가 노출되지 않도록 구성했습니다.

## 📚 개발을 통해 배운 점

### Spring Boot 계층 구조

Controller에서 모든 로직을 처리하지 않고 다음과 같이 역할을 분리했습니다.

```text
Controller
    ↓
Service
    ↓
Mapper
    ↓
Database
```

각 계층의 책임을 분리하면서 유지보수하기 쉬운 구조를 구성하는 방법을 학습했습니다.

---

### MyBatis

Mapper Interface와 XML을 분리하여 SQL을 관리하고 PostgreSQL 데이터베이스와 연동했습니다.

예약 시간 중복 검사와 예약 수정 시 현재 예약을 제외한 중복 검사 등을 구현하면서 SQL 조건을 활용한 데이터 검증 방법을 학습했습니다.

---

### Session

`HttpSession`을 활용하여 로그인한 사용자의 정보를 저장하고 로그인 여부에 따라 기능 접근을 제한했습니다.

또한 `LoginUser` DTO를 활용하여 비밀번호와 같은 민감한 정보가 세션에 저장되지 않도록 구성했습니다.

---

### 비밀번호 보안

BCrypt를 이용하여 비밀번호를 암호화하고 로그인 시 암호화된 비밀번호를 비교하는 방법을 학습했습니다.

평문 비밀번호 저장 방식에서 암호화 방식으로 개선하면서 웹 애플리케이션에서 사용자 인증 정보를 안전하게 관리하는 방법을 익혔습니다.

---

### 권한 검증

예약 수정 및 취소 과정에서 사용자가 요청한 예약 ID만을 기준으로 처리하지 않고 현재 로그인한 사용자가 해당 예약의 소유자인지 확인하도록 구현했습니다.

이를 통해 사용자별 데이터 접근 권한을 검증하는 방법을 학습했습니다.

---

### JavaScript

예약 날짜와 시간에 대한 클라이언트 측 검증을 구현하여 잘못된 입력을 사전에 방지하도록 구성했습니다.

---

### FullCalendar

DB에 저장된 예약 데이터를 FullCalendar 이벤트 데이터로 변환하여 캘린더 형태로 시각화했습니다.

예약자별 색상을 적용하여 여러 사용자의 예약을 직관적으로 구분할 수 있도록 구현했습니다.

---

### 단위 테스트

JUnit과 Mockito를 활용하여 예약 서비스의 핵심 비즈니스 로직을 테스트했습니다.

정상적인 예약뿐만 아니라 잘못된 시간 입력과 예약 시간 중복 등 실패해야 하는 상황까지 테스트하면서 기능 구현뿐만 아니라 예외 상황을 검증하는 방법을 학습했습니다.

또한 Mockito를 이용해 Mapper를 Mock 객체로 대체하여 실제 DB에 의존하지 않고 Service 계층의 로직을 독립적으로 테스트하는 방법을 익혔습니다.

---

### 환경변수 관리

DB 접속정보를 환경변수로 분리하여 소스코드에 실제 데이터베이스 비밀번호가 노출되지 않도록 구성했습니다.

개발 환경과 실행 환경에서 접속정보를 분리하여 관리할 수 있는 방법을 학습했습니다.

---

### 외부 접속 환경 구성

Cloudflare Tunnel을 이용하여 로컬에서 실행 중인 Spring Boot 애플리케이션을 외부에서 접속할 수 있도록 구성했습니다.

로컬 환경에서 구현한 웹 서비스를 외부 환경에서 직접 접속하여 로그인, 회의실 조회, 예약 및 관리자 기능을 테스트하면서 웹 애플리케이션의 실행 환경을 구성하는 과정을 경험했습니다.
